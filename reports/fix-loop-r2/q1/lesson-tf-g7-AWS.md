## Specific concerns, ruled

- (a) `TF_LOG_PATH` and `TF_LOG`. The pages do conflict, and not only on the two pages the writer names. Three positions:
  - Debugging page and environment-variables page: "even when TF_LOG_PATH is set, TF_LOG must be set in order for any logging to be enabled" (both say it, near-identical wording).
  - Troubleshooting tutorial: "If your TF_LOG_CORE or TF_LOG_PROVIDER environment variables are enabled, the TF_LOG_PATH variable will create the specified file and append logs generated by Terraform." Its walkthrough sets only `TF_LOG_CORE`/`TF_LOG_PROVIDER` plus `TF_LOG_PATH`.
  - Plugin-development Managing Log Output page: "set one or more logging environment variables to either JSON format or a verbosity level" (any one variable enables logging); it never mentions the `TF_LOG` requirement.
  - Ruling: the two Terraform CLI pages (debugging, environment variables) are explicit that `TF_LOG` must be set, and the tutorial and plugin page imply `TF_LOG_CORE`/`TF_LOG_PROVIDER` alone are enough. The only claim all sources agree on is that `TF_LOG_PATH` by itself enables nothing and needs some level variable. The lesson body quotes the explicit CLI sentence verbatim (fine) and then says "Always set a level variable as well" and, in the tip, "a level variable such as `TF_LOG`" (the safe reconciliation). It never tells the student the tutorial behaves differently. See AWS-Lg7-001. Questions: key may be "`TF_LOG_PATH` alone enables no logging"; never make "`TF_LOG_CORE` + `TF_LOG_PATH` writes nothing" or "... writes a file" a key or the only refutation of a distractor.
- (b) Override semantics and levels. Level list and order: exact (TRACE, DEBUG, INFO, WARN or ERROR, "in order of decreasing verbosity"; TRACE "Most verbose", ERROR "Least verbose"). The managing page also lists `OFF - Turns off logging for that logger.` (AWS-Lg7-003). Precedence: "TF_LOG overrides all other logging variables" plus the single worked example (`TF_LOG=TRACE`, a provider-specific variable at WARN, all providers log at TRACE). That is the entire documented evidence: it is on a plugin-development page, the Terraform CLI debugging page says nothing about precedence, and no example shows `TF_LOG_CORE` being overridden. The lesson's "wins over the narrow ones" is accurate to the table. See AWS-Lg7-002. `TF_LOG_CORE` "Does not include providers" and the "subset of the logs" sentence are exact.
- (c) `TF_LOG=JSON`. Exact: "outputs logs at the TRACE level or higher, and uses a parseable JSON encoding", warning "not considered a stable interface". The lesson's tip "a parseable TRACE-level format" drops "or higher"; TRACE is the top level, so no practical difference. PASS. The managing page adds "This format is not guaranteed to be stable between releases." (not needed).
- (d) `terraform output`. By-name and ephemeral behaviour: exact (see rows 65-67; the page example is `terraform output password` printing the value). `-raw` limits: exact ("it only supports string, number, and boolean values. Use -json instead for processing complex data types"); the page elsewhere says "works only with values that Terraform can automatically convert to strings", the same limit. Root-module-only: exact. The lesson never states that a plain `terraform output NAME` for a string prints it in quotes while `-raw` does not; the page's examples show that (`"my-app-alb-..."` versus raw). A "which prints without quotes" question would rest on page examples, not lesson text. Optional addition in AWS-Lg7-008. PASS otherwise.
- (e) `state push`. Exact. Two checks, "Differing lineage" and "Higher remote serial"; "Both of these safety checks can be disabled with the -force flag. This is not recommended."; with checks disabled "the destination state will be overwritten". The page's rationale for the checks is "you may lose data" (lineage) and "data ... that isn't accounted for" (serial); the lesson's Warnings overstate it: AWS-Lg7-006.
- (f) `import` block arguments and version floors. `identity`, `for_each` and `provider` appear in the block page's configuration model (`identity` "mutually exclusive with id"; `for_each` "map or set of strings"; `provider` reference). I searched the block page, the import overview, the generating-configuration page and the import tutorial for any minimum version for `identity`, `for_each` or `provider`: none is stated. The only floors on these pages are "Terraform v1.5+" (tutorial prerequisite and "As of Terraform 1.5 ... configuration to import") and "Configuration generation is available in Terraform v1.5 as an experimental feature". `show -json` on `state show` needs v1.16 (state/show page; the lesson correctly omits it). Ruling: the docs do not gate `identity` or `for_each` by version; the lesson states no floor (correct); questions must state none either. The lesson's wording "`identity` ... for providers that define one" is not on the page: AWS-Lg7-004.
- (g) "This lesson's inference" sentence (7c). Acceptable and honest as written: the quoted note is about provider development ("there may be sensitive data which should not be present in log messages or structured log fields", on the filtering page), nothing in the docs says a log "contains secrets", and the lesson labels the advice as its own. Keep it; do not drop. The Warnings bullet repeats the advice without the label: AWS-Lg7-006. Questions must treat it as advice, never as "the docs say logs contain secrets".

## Findings

**AWS-Lg7-001 (Medium, 7c, "Saving the log").** The lesson states only the CLI pages' `TF_LOG`-required rule. The troubleshooting tutorial (which the lesson also cites for core/provider logs) sets `TF_LOG_PATH` with only `TF_LOG_CORE`/`TF_LOG_PROVIDER` and says it works, so a student who has read both pages meets a contradiction the lesson hides, and a question on it could be challenged.
- Fix: after the `TF_LOG_PATH does not turn logging on by itself` bullet add: "The troubleshooting tutorial words it differently: "If your TF_LOG_CORE or TF_LOG_PROVIDER environment variables are enabled, the TF_LOG_PATH variable will create the specified file and append logs generated by Terraform." The one point every page agrees on is that `TF_LOG_PATH` alone enables nothing, so set `TF_LOG` (or `TF_LOG_CORE` or `TF_LOG_PROVIDER`) with it." Add a claim row for the tutorial sentence (url: `https://developer.hashicorp.com/terraform/tutorials/configuration-language/troubleshooting-workflow`; the sentence is verbatim, 25 words, so quote "the TF_LOG_PATH variable will create the specified file and append logs generated by Terraform." (14 words)). Then the 7c tip's "a level variable such as `TF_LOG`" is consistent.
- Question guidance: see concern (a).

**AWS-Lg7-002 (Low, 7c, "Core logs versus provider logs").** The precedence rule is on the plugin-development page only, and its sole example is a provider-specific variable. - Fix: in the `TF_LOG` bullet say "The plugin-development page's table says `TF_LOG` ..." and keep the example. Question guidance: the only supported precedence key is "with TF_LOG=TRACE and a provider-specific variable at WARN, providers log at TRACE"; do not build a key on `TF_LOG_CORE` versus `TF_LOG` conflicts.

**AWS-Lg7-003 (Low, 7c, level list).** The managing page lists a sixth value, "OFF - Turns off logging for that logger." The lesson gives five levels and later "set it to off" only. A distractor like "OFF is the least verbose level" has no taught refutation.

**AWS-Lg7-004 (Low, 7a, "What the import block can express").** "`identity` is the alternative for providers that define one" is not on any page; the block page says "You can only import resources that are supported by the provider" and that the keys and values are "specific to the resource type and provider".

- Fix: "In the tutorial the plan after generation proposes replacing the container "due to the default value of the env parameter returned by the provider," and a later plan carries the comment "# Warning: this will destroy the imported resource."" Drop "the tutorial warns it is verbose" (the page says the config "contains all possible arguments"; "verbose" is the lesson's word). **AWS-Lg7-006 (Low, Warnings).** (1) "`terraform state pull` print state values, including sensitive ones, in plain text" has no page support for pull specifically; the support is that state can hold secrets (6d Warnings, g2).
